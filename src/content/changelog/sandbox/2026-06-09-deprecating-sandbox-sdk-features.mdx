We are marking several legacy Sandbox SDK APIs as deprecated in the primary branch and publishing their replacements on the `next` branch. Existing projects should migrate as soon as possible. New projects should use `@cloudflare/sandbox@next` today.

Install the `next` branch with:

<PackageManagers pkg="@cloudflare/sandbox@next" />

For npm, this runs `npm install @cloudflare/sandbox@next`.

The deprecated APIs remain available in the primary branch until July 31, 2026. The `next` branch removes or replaces them so you can test the migration before the next stable release.

## HTTP and WebSocket transports

HTTP and WebSocket transports are removed in `next`. RPC is the supported transport path.

Before installing `next`, update the `SANDBOX_TRANSPORT` variable to `rpc` or remove code that forces the `http` or `websocket` transport. For more information, refer to [Transport modes](/sandbox/configuration/transport/).

## Execution APIs

The execution APIs are being consolidated. `exec()`, `execStream()`, and `startProcess()` move to a single `exec()` model that aligns with the Containers `container.exec()` API.

The new `exec()` API starts a process and returns a process object for output, streaming, exit status, and lifecycle control. Exact Sandbox SDK examples will be added to the migration guide when the final TypeScript interface lands on `next`.

## Default sessions

Hidden default sessions are removed in `next`, and the `enableDefaultSession` flag is removed from `getSandbox()`.

Top-level operations run sessionlessly by default. Use [`sandbox.createSession()`](/sandbox/api/sessions/) when you need shell state such as the current working directory or exported environment variables to persist across calls.

## Plugins and extensions

Code Interpreter, Git, and PTY support are moving out of the core SDK and into plugins. Plugins are imported from `@cloudflare/sandbox/<plugin>`, attached to the Sandbox instance with a `with<Plugin>(this)` helper, and expose the same public interfaces through a namespace on the sandbox instance.

The `next` branch also introduces an extension API for adding reusable Sandbox capabilities outside the core SDK.

## Next steps

To migrate, refer to [Migrate to Sandbox SDK next](/sandbox/guides/migrating-to-next/). We also provide an [agent skill](/sandbox/guides/migrating-to-next/SKILL.md) to help with the migration.
