[Flue](https://flueframework.com/) is a TypeScript harness framework for building agents and agent-backed workflows. On Cloudflare, Flue builds your project into a Worker and uses the Agents SDK runtime for Durable Object-backed agent instances.

## Start with an agent prompt

The fastest way to get started is to let your coding agent follow Flue's setup guide and make the project-specific choices with you.

<CopyPromptButton prompt={fluePrompt} />

Paste the prompt into Claude Code, Codex, Cursor, OpenCode, or another coding agent. The prompt tells the agent to read Flue's setup guide, create a Cloudflare-targeted Flue project, configure Wrangler migrations, and explain how the generated Worker maps onto Cloudflare.

The agent should help you choose:

- The agent or workflow you want to build
- The Flue source layout for your project
- The model provider and model specifier
- The Cloudflare target and `wrangler.jsonc` migration entries
- Any sandbox strategy the agent needs

When the generated project is ready, run it locally with Flue's Cloudflare target:

<PackageManagers type="exec" pkg="flue" args="dev --target cloudflare" />

Build the Cloudflare Worker artifact:

<PackageManagers type="exec" pkg="flue" args="build --target cloudflare" />

Deploy with `wrangler`:

<PackageManagers type="exec" pkg="wrangler" args="deploy" />

## What runs where

The following table shows how a Flue application maps onto Cloudflare.

| Part                               | Runs in                          | Notes                                                                                                                  |
| ---------------------------------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Flue Worker entrypoint             | Cloudflare Worker isolate        | Generated by `flue build --target cloudflare`; owns HTTP and custom Flue routing                                       |
| Route middleware                   | Cloudflare Worker isolate        | Runs before Flue admits work into a generated Durable Object                                                           |
| `FlueRegistry`                     | Durable Object                   | Coordinates generated Flue runtime metadata                                                                            |
| `FlueAssistantAgent`               | Durable Object                   | Owns the `assistant` agent instance selected by `:id`                                                                  |
| Session history and accepted input | Durable Object SQLite            | Stores conversation state and queued accepted agent input                                                              |
| Model calls                        | Workers AI or external providers | `cloudflare/*` model specifiers use Workers AI; other providers use Worker secrets                                     |
| Default virtual sandbox            | Flue runtime memory              | Uses Flue's lightweight in-memory workspace; it is not a separate Linux container and is not durable workspace storage |
| Cloudflare Sandbox                 | Cloudflare Containers            | Optional `@cloudflare/sandbox` integration for git, package managers, native binaries, or persistent Linux workspaces  |

Keep conversation state and workspace state separate. Durable Object SQLite preserves Flue session history, but it does not make files in the default virtual sandbox durable. Use [Sandbox](/agents/tools/sandbox/) when the agent needs an isolated Linux environment or a longer-lived workspace.

Flue can also generate workflow endpoints at `/workflows/:name`. These are Flue workflow invocations, not [Cloudflare Workflows](/workflows/) checkpoints. Use Cloudflare Workflows when you need step-level durable orchestration.

## Agents SDK parts Flue uses

Flue does not replace the Agents SDK runtime. It builds on the runtime and owns the higher-level harness.

| Agents SDK part                  | How Flue uses it                                                                                                                  |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| Durable Object-backed agent base | Flue generates the Durable Object classes instead of requiring you to write `extends Agent` yourself                              |
| Durable Object SQLite            | Generated Flue classes use `new_sqlite_classes` for durable session and execution state                                           |
| Durable execution fibers         | Flue uses SDK durability APIs such as `runFiber` for durable admission and interruption handling                                  |
| Alarms                           | Flue and the Agents SDK use alarms for scheduled runtime work and alarm multiplexing                                              |
| Native lifecycle APIs            | Flue exposes an extension point for SDK methods such as `onStart()`, `schedule()`, `scheduleEvery()`, `queue()`, and `setState()` |

Flue owns `fetch()` composition, generated route handling, `onRequest()`, `onFiberRecovered()`, and `alarm()` in its generated classes. Do not override those methods in a Flue-generated Durable Object. Use Flue's Cloudflare extension point when you need native Agents SDK hooks.

For example, add a recurring scheduled method to the generated `assistant` agent:

<TypeScriptExample filename=".flue/agents/assistant.ts">

```ts
import { createAgent, type AgentRouteHandler } from "@flue/runtime";
import { extend } from "@flue/runtime/cloudflare";

export const description = "Answers Cloudflare Workers questions.";

export const route: AgentRouteHandler = async (_c, next) => next();

export default createAgent(() => ({
	model: "cloudflare/@cf/moonshotai/kimi-k2.6",
	instructions:
		"Answer Cloudflare Workers questions clearly. State uncertainty when you are not sure.",
}));

export const cloudflare = extend({
	base: (Base) =>
		class extends Base {
			async onStart() {
				await this.scheduleEvery(60, "heartbeat");
			}

			async heartbeat() {
				this.setState({ ...this.state, lastHeartbeatAt: Date.now() });
			}
		},
});
```

</TypeScriptExample>

Use Flue APIs for the harness itself: `createAgent()` for agent configuration, `harness.session()` for prompts and session work, Flue tools and skills for model capabilities, and Flue routing for `/agents/:name/:id` and `/workflows/:name` endpoints.
